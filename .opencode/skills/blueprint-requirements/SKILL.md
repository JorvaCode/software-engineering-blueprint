# Blueprint Requirements Skill

When a task starts from a feature, bug or technical request:

1. Identify the problem and objective.
2. Clarify scope and constraints.
3. Define functional and non-functional requirements.
4. Produce explicit acceptance criteria.
5. Identify dependencies, risks and assumptions.
6. Do not jump directly to implementation when important requirements are ambiguous.
7. Keep the result traceable to the requested change.

Use `templates/requirement.md` as the preferred structure.
