# Git Standard

## Branches
Use short-lived branches for changes.

## Commits
Prefer small, meaningful commits that explain the change.

## Pull requests
Every non-trivial change should be reviewable through a pull request where the team workflow supports it.

## Main branch
The main branch should remain in a buildable/testable state.

## Traceability
Reference the requirement or issue from the pull request/commit when practical.
